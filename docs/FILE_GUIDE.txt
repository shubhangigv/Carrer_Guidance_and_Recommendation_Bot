1. THE BIG PICTURE: HOW THE FILES WORK TOGETHER
==========================================================================================

When the server starts (uvicorn backend.main:app --reload):

  backend/main.py  starts the app
     -> backend/db.py               connects to MySQL and creates/updates the tables
                                    (database/schema.sql + database/migrations/*.sql)
     -> ml/baseline_recommender.py  loads O*NET (from MySQL, or from data/raw/onet/ files)
     -> ml/localise.py, config/     short titles, India rules, industries
     -> ml/preferences.py           adds work-setting data, reads config/areas.csv, course_areas.csv
     -> ml/field_model.py           TRAINS the Logistic Regression on data/raw/survey/responses.csv
     -> ml/semantic.py              loads Sentence-BERT in the background (text matching)

When a student takes the quiz and opens "My matches":

  Browser: frontend/app/quiz.js  (the questions)
     -> frontend/app/api.js         sends the answers to the server   (POST /assessment)
     -> backend/main.py             checks them (backend/schemas.py), saves them (backend/repository.py)
  Browser: frontend/app/matches.js asks for matches                    (GET /recommend)
     -> backend/main.py -> backend/deps.py  personal_recommend()
        -> ml/preferences.py        areas, filters, weak points, grouping
           -> ml/field_model.py     predicts a field (if no areas picked)
           -> ml/recommender_v3.py  scores every career (engine v3)
              -> ml/recommender_v2.py  readiness, ranges, diversity, reasons
                 -> ml/baseline_recommender.py  shared maths, O*NET data
     <- the 10 careers with reasons go back to matches.js, which draws them

Other pages follow the same pattern:
  career.js   -> GET /careers/{id}, /careers/{id}/requirements, /careers/{id}/pathway
                 (backend/main.py, backend/routes/roadmap.py -> ml/career_needs.py, ml/pathways.py)
  roadmap.js  -> /roadmap/{id}           (backend/routes/roadmap.py -> ml/career_needs.py)
  explore.js  -> /industries, /careers/search   (backend/routes/explore.py, backend/main.py)
  assistant.js-> /assistant/chat          (backend/routes/assistant.py -> backend/assistant.py -> Gemini)
  quiz text box -> /match/text            (backend/routes/assistant.py -> ml/semantic.py)

Results for the report are made separately, by experiments/*.py, from O*NET + the survey file,
and written into docs/results/. experiments/report_tables.py turns them into the report tables.

3. ml/ - THE "BRAIN" (all recommendation logic; no website code here)
==========================================================================================

baseline_recommender.py  Engine v1 (Pearson correlation) AND the O*NET loaders used by everything:
                         load_onet() reads the O*NET text files, load_from_mysql() reads MySQL.
                         Also the skill/subject maps and SOC field names. Foundation of all engines.
recommender_v2.py        Engine v2: readiness scores (do your levels meet the career's levels),
                         score ranges for "can't assess" answers, follow-up questions, field diversity
                         (max 2 per field in the top 5), reasons and skill gaps, target career.
recommender_v3.py        Engine v3 = v2 + "strength fit" (are your strongest skills the ones the career
                         relies on). THE ENGINE THE WEBSITE USES. Holds the weights 0.25 / 0.30 / 0.15.
field_model.py           The trained ML model: Logistic Regression that predicts the career FIELD from
                         the 22 quiz answers (+ branch). Trained in memory at server start from the
                         survey file; never saved.
preferences.py           Personalisation on top of v3: chosen areas, course, work-setting and
                         further-study filters, weak-point clash rule, "Not for me", grouping into
                         "In your areas" (7) + "Also worth a look" (3), the predicted-field path.
semantic.py              Text matching: turns the student's own words into careers using Sentence-BERT
                         (all-MiniLM-L6-v2), or TF-IDF if Sentence-BERT is not installed.
career_needs.py          Every important skill/knowledge of a career, marked "You have this" /
                         "Skills to build", and the step-by-step roadmap.
pathways.py              "How to get there": Indian education routes (config/career_paths.csv),
                         stream after Class 10, education shares, career ladder, courses.
localise.py              India adaptation: short job titles, unique titles ("Professor (Biology)"),
                         India exclusions, industries, salaries (only from cited sources).
survey.py                Reads the Google Form CSV, turns each response into engine input and ML
                         features; ANALYSIS_CUTOFF = 87 (first 87 responses = main results).
__init__.py              Empty; makes ml/ a Python package so "from ml.x import y" works.


==========================================================================================
4. backend/ - THE SERVER (FastAPI)
==========================================================================================

main.py          Starts the app, loads all data at startup, and defines the main website
                 addresses: /health, /auth/register, /auth/login, /me, /assessment, /recommend,
                 /quiz/options, /feedback/... ("Not for me", ratings), /careers/search,
                 /careers/{id}, /target/{id}. Also serves the website at /app/.
deps.py          Shared pieces for all endpoint files: AppContext (all loaded data), the login check,
                 which engine to use (ENGINE_VERSION), personal_recommend().
schemas.py       The exact shape of every request and reply (Pydantic). Rejects bad input, e.g. a
                 rating of 7, with a clear error. Also what /docs shows.
repository.py    Saving and reading students, answers, recommendations, hidden careers, ratings.
                 Two versions: SqlRepository (MySQL) and MemoryRepository (no MySQL / tests).
db.py            The MySQL connection (settings from .env) and update_schema(), which runs
                 database/schema.sql and all migrations at startup.
security.py      Password hashing (bcrypt) and login tokens (JWT).
assistant.py     The chatbot (RAG): finds the career records for a question, sends them with the
                 rules to Google Gemini, returns the answer. Retries and backup models when busy;
                 "offline" answer without a key.
routes/explore.py    /industries, /industries/{id}: browse careers by industry.
routes/roadmap.py    /careers/{id}/requirements, /roadmap/{id}, /roadmap/{id}/progress, /roadmaps,
                     /careers/{id}/pathway.
routes/assistant.py  /match/text (own words -> careers), /assistant/status, /assistant/chat.
routes/__init__.py, __init__.py   Package markers.

9. experiments/ - THE SCRIPTS THAT PRODUCE EVERY RESULT
==========================================================================================

Run each with: python experiments\<name>.py   (outputs go to docs/results/)

On the survey (main results use the first 87 responses):
  survey_analysis.py   Survey counts and charts (who answered, counsellor, clarity) -> problem statement.
  survey_insights.py   Answer quality, branch vs aim, which answers separate fields (eta squared).
  hit_rate.py          Is the student's aimed field in their top 1/3/5? Engines v1, v2, v3 vs random.
  tune_weights.py      Tries ~200 weight sets with cross-validation (result: kept the hand weights).
  ml_compare.py        Logistic Regression vs Random Forest vs SVM vs majority vs the engine.
  model_features.py    Which inputs the field model should use (answers, + branch, ...).
  hybrid.py            ML field + engine v3 (what the website does), cross-validated.
  later_responses.py   The same evaluations on ALL 139 responses -> docs/results/survey/later/.
  user_test.py         Summarises students' 1-5 ratings of their own matches (user test).

On O*NET with synthetic students (checks of the formulas, not accuracy):
  self_match.py           Can each method find the career a synthetic student was copied from?
  weight_sensitivity.py   Does the top 5 change if a weight changes by 10%?
  masking.py              What happens when answers are "can't assess"?
  summarise.py            Writes docs/results/summary.md from those three.
  common.py               Shared helpers for these three.

Report:
  report_tables.py     Builds docs/report/results_tables.md from all results files (no number
                       typed by hand). Run it after any experiment.
